# Standardized record replay

B3 implements the frozen 84-record sample without inserting requests or selecting successful original conclusions. It imposes creation-time order within each project. It uses the same pinned dependency/runtime recipe, full tests/ command, isolation and whole-tree policy as B2. B1 refusal of a current head does not exclude older sampled states: every selected record is attempted. The project with no observed test workflow remains present with zero records.

Each acquired ordinary source is inventoried, and identity includes its bytes/modes, the fixed command, image digest and declared policy. Source archives precede inventory refusal, preserving unsupported symlink cases. Each reconstructable record receives an actual direct fresh full-tree oracle with the complete node/phase evidence. This is research validation of every request, including hits. It is not a claim that a deployed hit requires a new execution or that original CI ran that test command.

Receipt and native services each retain their root path and private store across records. For each previously unseen successful source identity, the externally scoped candidate authority is renewed, then each service actually executes. The state becomes qualified in the replay only if both nonempty staged outcome digests equal the full-tree oracle. A later source-equivalent record must match the prior fresh digest and actually return historical success from both services. Rejected states are not admitted on a later occurrence. A later fresh failure or changed digest at a formerly successful identity is retained as contradictory evidence and prevents a subsequent accepted hit. No automatic proof of Python determinism is claimed.

Per-record dispositions include unavailable/unsupported source, missing fresh evidence, fresh test failure, previously refused qualification, outcome instability, staged disagreement, technical failure, qualified miss and actual eligible hit. Original conclusion and run_attempt remain separate fields. A cancelled or action-required workflow with an executable source remains a counterfactual replay record, never evidence of original execution. Intermediate retry history is unknown.

The endpoint is eligible actual hits divided by all 84 selected records, with per-project denominators and reconstructable-source denominators shown alongside it. Content-equivalent records without correct execution evidence are not hits. Full-tree identity is deliberately conservative; this experiment does not estimate an optimal dependency-aware cache's opportunity. The historical-status demand assumption is hypothetical. Source-equivalent CI records need not represent a user willing to accept historical status.

B2 supplies complete operational cost comparisons and qualification sensitivity. B3 retains acquisition, source-renewal, authority, oracle and service costs as a provenance ledger; it does not infer a CI speedup by charging or removing the research oracle arbitrarily. In a counterfactual deployment, the first state qualification would require one independent oracle plus its producer; validation of later hits is research-only. Unknown human qualification remains unknown. No B3 timing superiority or original CI cost claim is planned. Fixed receipt-before-native order is therefore not used for a comparative timing claim.

This protocol and implementation are frozen before B3 execution. A 45-minute public hosted job budget is a resource limit, not an outcome filter. If interrupted, every begun record and all remaining unreached IDs remain visible; a continuation must preserve the prefix and explicitly record any lost process/cache state rather than silently reconstructing hits from SHA alone.
