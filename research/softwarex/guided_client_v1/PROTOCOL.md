## Prospective sequence and denominators

1. In a fresh isolated fixture, create the exact original reviewed manifest and
   external synthetic-only authority. Record unchanged source/install identities.
2. Through one actual installed-server STDIO session, initialize, capture
   `tools/list`, call `doctor`, and seed one successful normal `run_tests` call.
   Preserve all requests, raw responses, schema, readiness, and fresh seed result.
   These are non-model setup operations: two tool calls plus discovery, not
   model decisions or four new agent tasks. Verify the advertised schema matches
   the installed/source contract and permits only `task`, `root`, and `verify`.
3. Run exactly two separate ephemeral model turns: a status-only need accepting
   prior success, then a need for freshly executed validation. The model chooses
   arguments; never place gold argument values or expected outcomes in these
   prompts. Permit one `run_tests` call per turn. Both prompts include the same
   API card. After each successful turn, execute the original fixture directly
   in the pinned read-only, network-disabled container as a separate fresh oracle.
4. Only after both decisions succeed, run six fixed no-tool interpretation
   turns: actual non-model fresh seed, actual model reuse, actual model fresh
   verification, controlled fresh failure, controlled refusal, and actual reuse
   where a fresh diagnostic transcript is required. The seed remains clearly
   non-model; the controlled failures remain clearly synthetic.
5. Stop after any live decision protocol/tool/semantic failure or fresh-oracle
   failure. During interpretation, continue after semantic mistakes only; stop
   after a protocol boundary failure. No retries, replacement cases, corrective
   examples, or feedback. Maximum eight model turns, 120 seconds each, 2 MiB per
   stdout/stderr stream. Preserve timeouts, malformed output, refusal, and drift.
